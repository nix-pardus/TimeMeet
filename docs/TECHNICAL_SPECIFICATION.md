# Техническое задание: TimeMeet

**Версия 2.6.4**

## 1. Цель проекта

TimeMeet — бесплатное open-source веб-приложение на русском языке для согласования времени созвонов и встреч групп людей. Функционально повторяет основной сценарий when2meet.com, но с современным интерфейсом, поддержкой часовых поясов и автоматическим поиском лучших интервалов.

Основной сценарий одной встречи:


```
Свободная сетка → анализ доступности → выбор организатором итогового интервала → итоговое время
```

Участники отмечают свою доступность на тепловой карте. Система рассчитывает лучшие интервалы. Организатор выбирает итоговый интервал и закрывает встречу.

Двухэтапное голосование отложено на будущее.

## 2. Основные принципы

- Бесплатное использование.
    
- Open source под лицензией MIT.
    
- Голосование без регистрации по ссылке.
    
- В MVP все участники анонимные. Регистрация — задел на будущее.
    
- Поддержка часовых поясов.
    
- Все даты и время хранятся в UTC.
    
- Часовые пояса хранятся в формате IANA, например `Europe/Moscow`.
    
- Экспорт результатов в `.ics`, CSV и JSON.
    
- Никакого vendor lock-in.
    
- Минимальные расходы на инфраструктуру.
    
- Донаты только через внешние сервисы.

## 4. Состояния встречи

|Статус|Описание|
|---|---|
|`Active`|Активная встреча, идёт сбор доступности|
|`Closed`|Встреча закрыта, выбран итоговый интервал (или закрыта без него)|
|`Archived`|Встреча архивирована (soft-delete)|
|`Deleted`|Встреча удалена организатором|

При создании: `Status = Active`.

### 5.2. Meeting

|Поле|Тип|Описание|
|---|---|---|
|`Id`|PK|Идентификатор|
|`ShortCode`|string(10)|Уникальный код длиной 8–10 символов|
|`OwnerToken`|string|Токен организатора (для cookie)|
|`OwnerPasswordHash`|string?|Хеш пароля организатора. `null` = пароль не задан|

|`Description`|string(1000)?|Описание|

|`AllowRegistration`|bool|В MVP всегда `false`|
|`GridStartDate`|DateOnly|Дата начала сетки (TZ организатора)|
|`GridEndDate`|DateOnly|Дата окончания сетки (TZ организатора)|
|`GridStepMinutes`|int|Шаг сетки: 15, 30 или 60|
|`SelectedStartTime`|datetime?|Начало итогового интервала (UTC)|
|`SelectedEndTime`|datetime?|Окончание итогового интервала (UTC)|

|`DeletionReason`|enum?|`Manual` / `RetentionExpired`|

**Особенности:**

- **Сетка покрывает полные дни.** Границы дня — с 0:00 до 0:00 следующего дня в часовом поясе организатора.
    
- `TimeZone` фиксируется при создании и не меняется.
    
- **Пароль организатора — одно nullable-поле `OwnerPasswordHash`.** `null` = пароль не задан. Хеш через `PasswordHasher<Meeting>`.
    
- `RetentionMode` задаётся при создании.
    
- `OwnerToken` хранится в HttpOnly-cookie сроком 90 дней.
    
- **Редактирование встречи в MVP отсутствует.**
    
- Поля `Phase`, `Deadline`, `FinalDeadline`, `DurationMinutes`, `SelectedTimeSlotId`, `AvailabilityMode`, `GridFrom`, `GridTo` не используются.
    

### 5.3. GridCell

|Поле|Тип|Описание|
|---|---|---|
|`Id`|PK|Идентификатор|
|`MeetingId`|FK → Meeting|Встреча|
|`StartTime`|datetime|Начало (UTC)|
|`EndTime`|datetime|Окончание (UTC)|

**Учёт DST:** количество ячеек в дне — 23, 24 или 25 часов. Ячейки генерируются обходом UTC с проверкой попадания в локальный день.

**Ограничение размера сетки:** `(GridEndDate - GridStartDate + 1) * (24 * 60 / GridStepMinutes) <= 1500`.

**Индексы:** `MeetingId`, `MeetingId + StartTime`.

|`ParticipantPasswordHash`|string?|Хеш пароля. `null` = пароль не задан|

|`UpdatedAt`|datetime|Дата обновления|

**Особенности:**

- **Имена уникальны в рамках встречи.** Индекс `UNIQUE (MeetingId, DisplayName)`.
    
- **Пароль участника — одно nullable-поле `ParticipantPasswordHash`.**
    
- `ParticipantToken` — 32 случайных байта, HttpOnly-cookie 90 дней.
    

### 5.5. Availability

## 6. Создание встречи

Страница: `/create`

**Поля формы:**

- Название встречи (до 100 символов).
    
- Имя организатора (до 50 символов).
    
- Необязательное поле «Пароль» (минимум 4 символа).
    
- Дата начала сетки.
    
- Дата окончания сетки.
    
- Шаг сетки: 15, 30 или 60 минут.
    
- Скрываемый блок "Дополнительные параметры"
    
    - Описание (до 1000 символов).
        
    - Часовой пояс организатора.
        
    - Режим хранения: «Хранить историю» / «Удалить через день после окончания».
        

**Валидация:**

- `GridStartDate >= today` (в TZ организатора).
    
- `GridStartDate <= GridEndDate`.
    
- Количество ячеек ≤ 1500.
    
- Часовой пояс — валидный IANA.
    
- Пароль, если задан, — минимум 4 символа.
    

**После отправки:**

1. Генерируется `ShortCode`.
    
2. Генерируется `OwnerToken`.
    
3. Вычисляется `OwnerPasswordHash` (если пароль задан).
    
4. Создаётся встреча со `Status = Active`.
    
5. Создаются `GridCell` с учётом DST.
    
6. Создаётся `Participant` организатора с `IsOrganizer = true`.
    
7. Cookie с `OwnerToken`.
    
8. Редирект на `/m/{ShortCode}`.
    

Поля `AllowAnonymous` и `AllowRegistration` устанавливаются автоматически: `true` и `false`.

Страница `/create` доступна из меню «Создать встречу» (см. 10.5) и через кнопку «Создать» на странице «Мои встречи» (`/meetings`).

## 7. Голосование участника

URL: `/m/{ShortCode}`

**Организатор проходит тот же сценарий.**

### 7.1. Если cookie с `ParticipantToken` есть

Участник определяется автоматически, загружаются прежние отметки.

### 7.2. Если cookie нет — форма входа

Показываются название, описание, имя организатора и две секции:

- **«Я здесь впервые»** — имя + чекбокс «Защитить паролем» + поле пароля.
    
- **«Восстановить доступ»** — имя + пароль.
    

**Создание участника:** проверка уникальности имени, создание `Participant`, генерация токена, cookie.

**Восстановление:** поиск по `DisplayName`, проверка пароля через `PasswordHasher<Participant>`, установка cookie.

### 7.3. Опциональность пароля

Без пароля восстановление после потери cookie невозможно. В UI — предупреждение.

### 7.4. Ограничения MVP

Регистрация, вход в аккаунт — не реализуются. При потере cookie без пароля участник может создать нового `Participant` с другим именем.

Ссылки навигации:

- Участник, не организатор: внизу страницы `/m/{shortCode}` — ссылка «Создать свою встречу» → `/create`.
    
- Организатор: ссылка «Мои встречи» → `/meetings` рядом с кнопкой «Управление встречей».

## 8. Тепловая карта

### 8.1. Раскладка

- Столбцы — дни. Строки — часы.
    
- Внутри часа — 4 / 2 / 1 ячейка по `GridStepMinutes`.
    
- Подпись часа — слева. Между ячейками — тонкая граница, между часами — заметнее.
    
- Скролл: вертикальный по часам, горизонтальный по дням, первый столбец фиксирован.
    

### 8.2. Режимы

- **«Моя доступность»** (по умолчанию) — редактирование.
    
- **«Показать всех»** — просмотр.
    

### 8.3. Режим «Моя доступность»

Цикл: `Не отмечено → Свободен → Если нужно → Не отмечено`.

Цвета: зелёный / жёлтый / серый. Автосохранение — debounce 1–2 секунды.

### 8.4. Режим «Показать всех»

Только просмотр. Цветовая шкала от серого до насыщенно-зелёного; жёлтый — IfNeeded; смешанный — оба.

Tooltip:

```
10:00–11:00, Пн 12 окт
Свободны: Иван, Мария, Пётр (3 из 8)
Если нужно: Аня (1)
Не могут: Олег, Катя, Дима, Саша (4)
```

### 8.5. Галочка «Ни одно время не подходит»

Отмечена — все `Availability` удаляются, `HasNoSuitableTime = true`. Снята — обратно. При начале разметки — снимается автоматически.

### 8.6. Часовой пояс участника

Мелким шрифтом рядом с сеткой: `Иван Петров · Europe/Moscow · UTC+3`.

### 8.7. Мобильная отрисовка

Горизонтальный и вертикальный скролл, ячейки ≥ 24×24 px.

### 8.8. Пустое состояние

> «Пока никто не отметил доступность. Поделитесь ссылкой с участниками.»
> 
> [Скопировать ссылку]

## 9. Расчёт лучших интервалов

Раздел доступен **всем участникам**. Список лучших интервалов отображается **под тепловой картой**.

Кнопка: **«Найти лучшие интервалы»**.

### 9.1. Определение интервала

**Интервал** — это непрерывная последовательность соседних ячеек `GridCell` с одинаковым набором участников, имеющих активный ответ в каждой ячейке.

Активным считается ответ `Availability` со статусом `Available` или `IfNeeded`. Участник без записи в ячейке считается неактивным в этой ячейке.

Таким образом, интервал — это участок «живой зоны», в котором состав участников с активными ответами не меняется. Интервал разделяется, если:

- меняется набор участников со статусом `Available` или `IfNeeded`;
    
- появляется ячейка, в которой нет активных ответов;
    
- между соседними ячейками есть временной разрыв.
    

Смена статуса конкретного участника между `Available` и `IfNeeded` сама по себе интервал не разделяет. Она учитывается при определении худшего статуса участника внутри интервала.

**Проголосовавшим** считается участник с хотя бы одной записью `Availability` или `HasNoSuitableTime = true`.

**Границы интервала:**

- Начало — первая ячейка, где у участника есть активный ответ.
    
- Конец — последняя соседняя ячейка перед изменением набора активных участников или разрывом.
    
- **Интервал может пересекать полночь и охватывать несколько дней.** Если набор активных участников не меняется, переход через полночь не разделяет интервал.
    

Несколько интервалов могут находиться внутри одной общей живой зоны. Это позволяет показывать отдельные альтернативы с разным составом участников, например вариант, где один участник отмечен как `IfNeeded`, а остальные доступны.

### 9.2. Категории участников внутри интервала

Для каждого проголосовавшего участника определяется его **худший статус** внутри интервала:

- **Available** — во всех ячейках интервала у него `Available`.
    
- **IfNeeded** — хотя бы в одной ячейке `IfNeeded`, но ни в одной нет отсутствия записи.
    
- **Cannot** — хотя бы в одной ячейке интервала у него нет записи.
    

Каждый участник попадает **ровно в одну** категорию. Категории не пересекаются.

Обозначения:

- `i` — число участников категории Available.
    
- `j` — число участников категории IfNeeded.
    
- `k` — число участников категории Cannot.
    

`i + j + k = общее число проголосовавших`.

### 9.3. Отображение списка

Список интервалов — таблица со столбцами. Сначала отображаются основные интервалы общего `Available`, затем — альтернативные интервалы с `IfNeeded` и/или отсутствующими участниками.

|Начало|Окончание|Продолжительность|Доступность|
|---|---|---|---|

**Формат столбца «Доступность»:**

- `i > 0, k = 0, j = 0` → **«все доступны»**
    
- `i > 0, k = 0, j > 0` → **«{i} доступны, {j} если нужно»**
    
- `i > 0, k > 0, j > 0` → **«{i} доступны, {j} если нужно, {k} не могут»**
    
- `i > 0, k > 0, j = 0` → **«{i} доступны, {k} не могут»**
    
- `i = 0, k > 0, j > 0` → **«{j} если нужно, {k} не могут»**
    

**Продолжительность** — в человекочитаемом формате: «3 часа», «1 час 30 минут», «45 минут», «2 дня 4 часа».

**Формат дат и времени** — `20.10.2026 12:00` (см. раздел 10.4).

**Пример:**

```
Начало              Окончание            Продолжительность   Доступность
20.10.2026 12:00    20.10.2026 15:00     3 часа              все доступны
20.10.2026 18:30    20.10.2026 20:00     1 час 30 минут      все доступны
```

### 9.4. Сортировка

Четыре группы в порядке:

1. **Все доступны** (`k = 0, j = 0`).
    
2. **С IfNeeded** (`k = 0, j > 0`) — сортировка по `j` **по возрастанию**.
    
3. **С отсутствующими** (`k > 0`) — сначала по `k` **по возрастанию**, потом по `j` **по возрастанию**.
    
4. **Без доступных, с IfNeeded, с отсутствующими** (`i = 0, j > 0, k > 0`) - сначала по `k` **по возрастанию**, потом по `j` **по возрастанию**.
    

**Дополнительная сортировка** внутри любой группы: по времени начала — **раньше выше**.

Интервалы сортируются по продолжительности **по убыванию**. При одинаковой продолжительности сохраняется сортировка по группе и времени начала.

### 9.5. Развёрнутый вид при клике

Каждая строка таблицы кликабельна. При клике открывается развёрнутый вид — детальная доступность каждого участника внутри интервала.

**Формат:**

- Если статус участника не меняется по всему интервалу:
    
    - `Иван: доступен весь интервал`
        
    - `Мария: если нужно весь интервал`
        
- Если статус меняется внутри интервала:
    
    - `Пётр: если нужно (12:00–14:00), доступен (14:00–15:00)`
        
    - `Аня: не может (12:00–13:00), доступна (13:00–15:00)`
        

Время указывается в часовом поясе текущего пользователя.

**Пример:**

```
20.10.2026 12:00 — 20.10.2026 15:00
  Иван:   доступен весь интервал
  Мария:  доступна весь интервал
  Пётр:   если нужно (12:00–14:00), доступен (14:00–15:00)
  Аня:    не может (12:00–13:00), доступна (13:00–15:00)
```

### 9.6. Пустые состояния

Если никто не проголосовал:

> «Пока никто не отметил доступность. Результаты появятся, когда кто-то проголосует.»

Если проголосовали, но ни одного интервала не найдено (например, все отметили «нет подходящего времени»):

> «Никто из проголосовавших не может участвовать ни в какое время.»

## 10. Интерфейс и навигация

### 10.1. Авторизация

Порядок проверки:

1. **Cookie `timemeet-owner-{shortCode}`** — если совпадает с `Meeting.OwnerToken`, доступ разрешён.
    
2. **Cookie нет, `OwnerPasswordHash != null`** — форма ввода пароля.
    
    При верном пароле — cookie устанавливается, редирект на `/manage/{shortCode}`.  
    При неверном — «Неверный пароль». Rate limiting.
    
3. **Cookie нет, `OwnerPasswordHash = null`** — страница:
    
    > **Доступ запрещён**
    > 
    > Эта встреча не защищена паролем. Войти можно только с того браузера, где она была создана.
    > 
    > Совет: в следующий раз задайте пароль при создании встречи — тогда доступ можно будет восстановить с любого устройства.
    > 
    > [Перейти к голосованию]
    

**Rate limiting:** 5 попыток / 5 минут / IP / `shortCode`.

### 10.2. Активная встреча

Вверху страницы `/manage/{shortCode}` — ссылка «← Мои встречи» → `/meetings`.

- Название, статус, режим хранения.
    
- Ссылка для участников, QR-код, кнопки шаринга.
    
- **Три категории участников:**
    
    - **Отметили доступность** — Иван, Мария, Пётр (3).
        
    - **Отметили «нет подходящего времени»** — Аня (1).
        
    - **Зашли, но не проголосовали** — Олег, Катя (2).
        
    - Для каждого проголосовавшего — его TZ.
        
- Тепловая карта.
    
- Список лучших интервалов.
    
- Кнопка «Найти лучшие интервалы».
    
- Кнопка закрытия встречи.
    
- Кнопка «Удалить встречу навсегда».
    

### 10.3. Закрытая встреча

- Итоговый интервал (или «Встреча закрыта без выбранного времени»).
    
- Кнопки экспорта `.ics`, CSV, JSON.
    
- Кнопка «Добавить в календарь» (скачивает `.ics`).
    

### 10.4. Формат отображения

- `Название встречи`
    
- `Описание встречи`
    
- `12 октября 2026, понедельник`.
    
- `10:00–12:00`.
    
- Часовой пояс: `10:00 (МСК)` или `10:00 (Europe/Moscow)`.
    

### 10.5. Навигация и меню

#### 10.5.1. Верхняя панель (AppBar)

Отображается на всех страницах приложения.

**Левая часть:** логотип «TimeMeet», кликабельный → `/`.

**Правая часть (десктоп, ширина ≥ 600 px):**

- «Мои встречи» — ссылка на `/meetings`.

- Переключатель темы (иконка 🌙 / ☀️).
    

**Правая часть (мобилка, ширина < 600 px):**

#### 10.5.2. Страница «Мои встречи» (`/meetings`)

Список встреч, созданных на текущем устройстве.

**Источник данных:** cookie `timemeet-owner-{shortCode}`.

**Загрузка (в `OnInitializedAsync`):**

1. Получить все cookie с префиксом `timemeet-owner-`.
    
2. Для каждого `shortCode` вызвать `IMeetingService.GetForOwnerAsync(shortCode, token)`.
    
3. Отбросить `null` и встречи со `Status = Deleted`.
    
4. Отсортировать по `CreatedAt DESC`.
    

**Карточка встречи:**

|Элемент|Значение|
|---|---|
|Заголовок|`meeting.Title`|
|Chip статуса|«Активна» (зелёный) / «Закрыта» (серый) / «Архивирована» (приглушённый)|
|Подзаголовок|`{GridStartDate}–{GridEndDate}` в TZ встречи, количество участников|
|Для `Closed`|+ итоговый интервал|
|Кнопка «Управление»|`/manage/{shortCode}`|
|Кнопка «Голосование»|`/m/{shortCode}` (только для `Active`)|
|Кнопка «Удалить»|Только для `Active` / `Closed`, с `confirm`|

**Пустое состояние:** «Вы пока не создали ни одной встречи.» + кнопка «Создать встречу» → `/create`.

**Ограничение:** не более 20 карточек — cookie-механизм ограничен 20 активными `owner`-cookie на браузер (см. раздел 14 «Безопасность»), поэтому страница показывает все доступные записи.

#### 10.5.3. Локальная навигация на внутренних страницах

- `/create` — вверху ссылка «← Мои встречи».
    
- `/m/{shortCode}` (участник) — внизу ссылка «Создать свою встречу» → `/create`.
    
- `/m/{shortCode}` (организатор) — кнопка «Управление встречей» (уже есть) + ссылка «Мои встречи» → `/meetings`.

- `/m/{shortCode}/restore` — ссылка «Вернуться к встрече» (уже есть).
    

#### 10.5.4. Скрытые служебные страницы

Не отображаются в меню и не связаны с ним:

- `/manage-access?token=…` — endpoint установки cookie.
    
- `/participant-access?token=…` — endpoint установки cookie.
    
- `/manage-login/{shortCode}` — легаси, удаляется.

## 11. Выбор итогового интервала и закрытие встречи

### 11.1. Закрытие с выбранным интервалом

Организатор выбирает интервал из списка и нажимает **«Закрыть встречу с этим интервалом»**.

**Система:**

1. Записывает `SelectedStartTime` и `SelectedEndTime` (UTC).
    
2. Устанавливает `Status = Closed`, `ClosedAt`.
    
3. Запрещает изменения голосов.
    
4. Показывает итоговое время всем участникам.
    

### 11.2. Закрытие без выбранного интервала

Организатор нажимает **«Закрыть встречу»** без выбора. Подтверждение:

> «Вы закрываете встречу без выбранного времени. Это значит, что встреча не состоится. Продолжить?»

`SelectedStartTime`/`SelectedEndTime` остались `null`. На странице встречи: «Встреча закрыта без выбранного времени.»

### 11.3. Автозакрытие

Отсутствует.

## 12. Жизненный цикл встречи

### 12.1. Архивация (KeepForever)

Через 90 дней после `GridEndDate` встреча переводится в `Status = Archived`. `GridCell`, `Availability`, `Participant` не удаляются.

Для `DeleteAfterLastDay` архивация не применяется.

**Глобальный query filter:**

```cs
modelBuilder.Entity<Meeting>()
    .HasQueryFilter(x => x.Status != MeetingStatus.Archived
                      && x.Status != MeetingStatus.Deleted);
```

### 12.2. Удаление по RetentionMode = DeleteAfterLastDay

Hangfire раз в сутки (03:00 UTC).

**Условие:** `RetentionMode = DeleteAfterLastDay` **и** в TZ организатора наступил день, следующий за `GridEndDate`.

**Удаляется:** `Availability`, `GridCell`, `Participant`, `Invitation`, `Meeting`.

### 12.3. Ручное удаление

Организатор нажимает **«Удалить встречу навсегда»** → подтверждение.

После подтверждения: дочерние сущности удаляются, `Meeting → Status = Deleted`, `DeletedAt = now`, `DeletionReason = Manual`. По ссылке `/m/{ShortCode}` — «Встреча удалена организатором.» Через 30 дней Hangfire удаляет `Meeting`.

## 14. Безопасность

- `ShortCode` — криптостойко.
    
- `OwnerToken`/`ParticipantToken` — `RandomNumberGenerator`, 32 байта.
    
- Пароли — `PasswordHasher<T>` (PBKDF2). `null` = пароль не задан.
    
- Cookie: `HttpOnly`, `Secure` в production, `SameSite=Lax`, 90 дней.
    
- `MaxLength`: `Title` — 100, `Description` — 1000, `OrganizerName`/`DisplayName` — 50.
    
- Rate limiting на создание встреч.
    
- Rate limiting на форму пароля организатора: 5 / 5 мин / IP / `shortCode`.
    
- Rate limiting на восстановление участника: 10 / 10 мин / IP / `shortCode`.
    
- Лимит: `participants × cells_per_meeting ≤ 50 000`.
    
- Уникальность имён в рамках встречи.
    
- CSRF через `UseAntiforgery`.
    
- **Ограничение на количество cookie:** не более 20 активных cookie с префиксом `timemeet-owner-` и 20 с префиксом `timemeet-participant-` на браузер. При установке новой cookie сверх лимита старые с тем же префиксом удаляются.

## 21. Итоговая схема процесса

```
Создание встречи (диапазон, шаг, режим хранения, опциональный пароль)  
↓  
Организатор попадает на страницу голосования как Participant  
↓  
Участники (включая организатора) отмечают доступность на тепловой карте  
↓  
Система рассчитывает непрерывные интервалы  
↓  
Список интервалов виден всем под картой (с сортировкой и развёрнутым видом)  
↓  
Организатор выбирает интервал (или закрывает без интервала)  
↓  
Встреча закрывается  
↓  
┌────────────────────────────────────┐  
│ RetentionMode = KeepForever?       | 
│ Да → архивация через 90 дней       |
│ Нет → удаление через день после    |
│ GridEndDate (TZ орг.)              |
└────────────────────────────────────┘  
↓  
Экспорт в календарь
```
