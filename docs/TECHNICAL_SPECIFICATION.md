# Техническое задание: TimeMeet

**Версия:** 2.5

## 1. Цель проекта
TimeMeet — бесплатное open-source веб-приложение на русском языке для согласования времени созвонов и встреч групп людей. Функционально повторяет основной сценарий when2meet.com, но с современным интерфейсом, поддержкой часовых поясов и автоматическим поиском лучших интервалов.
Основной сценарий одной встречи:

```text
Свободная сетка → анализ доступности → выбор организатором итогового окна → итоговое время
```
Участники отмечают свою доступность на тепловой карте. Система рассчитывает лучшие интервалы по отдельным ячейкам. Организатор выбирает итоговое окно и закрывает встречу.
Двухэтапное голосование (сбор доступности + финальное голосование по фиксированным слотам) отложено на будущее.

## 2. Основные принципы
- Бесплатное использование.
- Open source под лицензией MIT.
- Голосование без регистрации по ссылке.
- В MVP все участники анонимные. Регистрация — задел на будущее.
- Поддержка часовых поясов.
- Все даты и время хранятся в UTC.
- Часовые пояса хранятся в формате IANA, например `Europe/Moscow`.
- Экспорт результатов в `.ics`, CSV и JSON.
- Никакого vendor lock-in.
- Минимальные расходы на инфраструктуру.
- Донаты только через внешние сервисы.

## 4. Состояния встречи
Статус встречи:

| Статус | Описание |
| --- | --- |
| `Active` | Активная встреча, идёт сбор доступности |
| `Closed` | Встреча закрыта, выбран итоговый слот (или закрыта без него) |
| `Archived` | Встреча архивирована (soft-delete, данные сохранены) |
| `Deleted` | Встреча удалена организатором (данные удалены, осталась заглушка) |

При создании:

```text
Status = Active
```
Фазы в MVP не используются. Понятие фазы — задел на будущее.

### 5.2. Meeting
Встреча:

| Поле | Тип | Описание |
| --- | --- | --- |
| `Id` | PK | Идентификатор |
| `ShortCode` | `string(10)` | Уникальный код длиной 8–10 символов |
| `OwnerToken` | `string` | Токен организатора |
| `Title` | `string(100)` | Название встречи |
| `Description` | `string(1000)?` | Описание |
| `OrganizerId` | `FK → User?` | Организатор. В MVP всегда `null` |
| `OrganizerName` | `string(50)` | Имя организатора |
| `TimeZone` | `string(64)` | Часовой пояс организатора. Фиксируется при создании |
| `ParticipationMode` | enum | `LinkOnly` / `InvitedList`. В MVP всегда `LinkOnly` |
| `Status` | enum | `Active` / `Closed` / `Archived` / `Deleted` |
| `RetentionMode` | enum | `KeepForever` / `DeleteAfterLastDay` |
| `AllowAnonymous` | `bool` | В MVP всегда `true` |
| `AllowRegistration` | `bool` | В MVP всегда `false` |
| `GridStartDate` | `DateOnly` | Дата начала сетки (TZ организатора) |
| `GridEndDate` | `DateOnly` | Дата окончания сетки (TZ организатора) |
| `GridStepMinutes` | `int` | Шаг сетки: 15, 30 или 60 |
| `SelectedStartTime` | `datetime?` | Начало итогового окна (UTC). Может быть `null` после закрытия |
| `SelectedEndTime` | `datetime?` | Окончание итогового окна (UTC). Может быть `null` после закрытия |
| `CreatedAt` | `datetime` | Дата создания |
| `ClosedAt` | `datetime?` | Дата закрытия |
| `ArchivedAt` | `datetime?` | Дата архивации |
| `DeletedAt` | `datetime?` | Дата удаления |

Особенности:
Сетка покрывает полные дни. Границы дня — с 0:00 до 0:00 следующего дня в часовом поясе организатора.
TimeZone фиксируется при создании и не меняется.
RetentionMode задаётся при создании через радио-кнопки:
KeepForever — хранить историю (по умолчанию).
DeleteAfterLastDay — удалить через день после GridEndDate в часовом поясе организатора.
OwnerToken хранится в HttpOnly-cookie организатора сроком 30–90 дней.
Дополнительно при создании встречи организатору показывается ссылка управления с токеном в URL. Организатор может её сохранить и использовать для доступа без cookie.
В MVP все участники анонимные. Поля AllowAnonymous и AllowRegistration — задел на будущее.
Редактирование встречи в MVP отсутствует. После создания поля не меняются.
Поля Phase, Deadline, FinalDeadline, DurationMinutes, SelectedTimeSlotId, AvailabilityMode, GridFrom, GridTo больше не используются.
### 5.3. GridCell
Ячейка свободной временной сетки:

| Поле | Тип | Описание |
| --- | --- | --- |
| `Id` | PK | Идентификатор |
| `MeetingId` | `FK → Meeting` | Встреча |
| `StartTime` | `datetime` | Начало (UTC) |
| `EndTime` | `datetime` | Окончание (UTC) |

При создании встречи создаются ячейки на основе GridStartDate — GridEndDate и шага GridStepMinutes. Каждый день покрывается целиком: с 0:00 до 0:00 следующего дня в часовом поясе организатора.
Учёт DST: количество ячеек в дне зависит от перехода на летнее/зимнее время. День может длиться 23, 24 или 25 часов. Ячейки генерируются обходом UTC-времени с проверкой попадания в локальный день.
Ограничение размера сетки: количество ячеек на встречу не должно превышать 1500. Валидация на форме:

```text
(GridEndDate - GridStartDate + 1) * (24 * 60 / GridStepMinutes) <= 1500
```
Индексы:
MeetingId
MeetingId + StartTime
### 5.4. Participant
Участник встречи. В MVP всегда анонимный.

| Поле | Тип | Описание |
| --- | --- | --- |
| `Id` | PK | Идентификатор |
| `MeetingId` | `FK → Meeting` | Встреча |
| `UserId` | `FK → User?` | Пользователь. В MVP всегда `null` |
| `DisplayName` | `string(50)` | Имя участника |
| `TimeZone` | `string(64)` | IANA-часовой пояс |
| `ParticipantToken` | `string` | Токен участника |
| `HasNoSuitableTime` | `bool` | Участник отметил «нет подходящего времени» |
| `IsOrganizer` | `bool` | Участник является организатором |
| `CreatedAt` | `datetime` | Дата создания |
| `UpdatedAt` | `datetime` | Дата обновления |

ParticipantToken создаётся через RandomNumberGenerator, 32 случайных байта, хранится в HttpOnly-cookie сроком 30–90 дней.
Особенности:
HasNoSuitableTime = true означает, что участник явно заявил: «ни одно время мне не подходит». При этом все его Availability удаляются.
IsOrganizer = true устанавливается, если организатор тоже голосует.
### 5.5. Availability
Отметка доступности участника:

| Поле | Тип | Описание |
| --- | --- | --- |
| `Id` | PK | Идентификатор |
| `ParticipantId` | `FK → Participant` | Участник |
| `GridCellId` | `FK → GridCell` | Ячейка сетки |
| `Status` | enum | `Available` / `IfNeeded` |
| `CreatedAt` | `datetime` | Дата создания |
| `UpdatedAt` | `datetime` | Дата обновления |

Уникальность: одна запись на пару (ParticipantId, GridCellId). Индекс UNIQUE.
Особенности:
Статус Unavailable убран. Отсутствие записи = участник не может в это время.
При переходе ячейки в «Не отмечено» запись удаляется, а не помечается.

## 6. Создание встречи
Страница:

```text
/create
```
**Поля формы:**

- Название встречи (обязательное, до 100 символов).
- Описание (до 1000 символов).
- Имя организатора (обязательное, до 50 символов).
- Часовой пояс организатора (по умолчанию — определённый через `Intl.DateTimeFormat().resolvedOptions().timeZone`).
- Дата начала сетки.
- Дата окончания сетки.
- Шаг сетки: 15, 30 или 60 минут.
- Режим хранения (радио-кнопки):
  - Хранить историю встречи (по умолчанию).
  - Удалить через день после окончания встречи.

**Валидация:**

- `GridStartDate >= today` (в часовом поясе организатора).
- `GridStartDate <= GridEndDate`.
- Количество ячеек: `(GridEndDate - GridStartDate + 1) * (24 * 60 / GridStepMinutes) <= 1500`.
- Часовой пояс — валидный IANA.

**После отправки:**

- Генерируется `ShortCode` (криптостойко, 8–10 символов, base62).
- Генерируется `OwnerToken` (32 случайных байта).
- Создаётся встреча со `Status = Active`.
- Создаются `GridCell` — по всем дням от `GridStartDate` до `GridEndDate` с шагом `GridStepMinutes`, обходом UTC-времени с учётом DST.
- `OwnerToken` устанавливается в HttpOnly-cookie.
- Организатор перенаправляется на страницу голосования `/m/{ShortCode}`.
После редиректа организатору показывается модальное окно:
«Сохраните ссылку управления. Она даёт доступ к панели управления без cookie. Мы показываем её только один раз.»
https://timemeet.ru/manage/abc123xy?key=K7fPq2nM9x...
[Скопировать] [Понятно]
Ссылка больше нигде не отображается. Позже организатор может сгенерировать новую ссылку на панели управления (кнопка «Пересоздать ссылку»).
Поля AllowAnonymous и AllowRegistration устанавливаются автоматически: true и false.

## 7. Голосование участника
URL:

```text
/m/{ShortCode}
```
Организатор проходит тот же флоу. После создания он попадает сюда, вводит имя, становится Participant с IsOrganizer = true и голосует как обычный участник.
### 7.1. Первый вход
Показываются:
- название встречи;
- описание;
- имя организатора;
- поле имени (обязательное, до 50 символов);
- часовой пояс участника (определяется автоматически).
Часовой пояс определяется через:

```javascript
Intl.DateTimeFormat().resolvedOptions().timeZone
```
После продолжения:
- Создаётся `Participant`.
- Генерируется `ParticipantToken`.
- Токен устанавливается в HttpOnly-cookie.
- Пользователь возвращается на `/m/{ShortCode}`.
### 7.2. Повторный вход
При наличии cookie:
- участник определяется автоматически;
- загружаются его прежние отметки;
- имя и часовой пояс берутся из базы.
### 7.3. Ограничения MVP
Регистрация, вход в аккаунт и привязка Participant к User не реализуются.
Если участник потерял cookie, он может ввести то же имя повторно — система создаст нового Participant с тем же именем, и организатор увидит дубликат.
Если организатор потерял cookie и не сохранил ссылку управления — доступ к панели восстановить нельзя.

## 8. Тепловая карта
Тепловая карта — центральный элемент страницы голосования.
### 8.1. Раскладка
Столбцы — дни. Слева направо: 12 октября, 13 октября, 14 октября...
Строки — промежутки между часами часы. Сверху вниз: 00:00, 01:00, 02:00, ..., 23:00.
Внутри часа — несколько ячеек, расположенных вертикально в зависимости от GridStepMinutes:
- шаг 15 минут — 4 ячейки без подписей;
- шаг 30 минут — 2 ячейки без подписей;
- шаг 60 минут — 1 ячейка.
Подпись часа — слева от границы строки.
Ячейки внутри часа не подписываются.
Между ячейками внутри часа — тонкая серая граница (1px).
Между часами — более заметная, черная граница.
Скролл:
- вертикальный — по часам, если не влезает;
- горизонтальный — по дням, если дней больше, чем помещается;
- первый столбец (подписи часов) фиксирован.
### 8.2. Режимы отображения
Переключатель над картой:
«Моя доступность» (по умолчанию) — участник видит свои отметки и может их менять.
«Показать всех» — агрегированная карта, только просмотр.
### 8.3. Режим «Моя доступность»
Цикл кликов по ячейке:

```text
Не отмечено → Свободен → Если нужно → Не отмечено
```
Цвета:
| Статус | Цвет |
| --- | --- |
| `Available` | Зелёный |
| `IfNeeded` | Жёлтый |
| Не отмечено | Серый |

Изменения сохраняются автоматически с debounce 1–2 секунды.
### 8.4. Режим «Показать всех»
Только просмотр. Клики по ячейкам не работают.
Цветовая шкала:
Серый — 0 проголосовавших отметили эту ячейку.
Бледно-зелёный — 1 из N.
Насыщенно-зелёный — N из N.
Жёлтый оттенок — если в ячейке есть IfNeeded.
Смешанный цвет — если есть и Available, и IfNeeded.
Tooltip при наведении на ячейку:

```text
10:00–11:00, Пн 12 окт
Свободны: Иван, Мария, Пётр (3 из 8)
Если нужно: Аня (1)
Не могут: Олег, Катя, Дима, Саша (4)
```
### 8.5. Галочка «Ни одно время не подходит»
На самой карте, рядом с переключателем режимов.
Если отмечена — все Availability участника удаляются, HasNoSuitableTime = true.
Если снята — HasNoSuitableTime = false, карта возвращается в пустое состояние.
Если участник начинает отмечать ячейки, а галочка стоит — галочка снимается автоматически.
### 8.6. Отображение часового пояса
Рядом с сеткой отображается часовой пояс участника:

```text
Иван Петров · Europe/Moscow · UTC+3
```
Мелким шрифтом. Это снимает путаницу, если TZ участника отличается от TZ организатора.
### 8.7. Мобильная отрисовка
- Горизонтальный скролл по дням.
- Вертикальный скролл по часам.
- Первый столбец фиксирован.
- Ячейки крупные (минимум 24×24 px на тач-устройствах).
- Быстрый переход к «рабочему времени» (9:00–21:00) — опционально.
### 8.8. Пустое состояние
Если никто не отметил доступность:
«Пока никто не отметил доступность. Поделитесь ссылкой с участниками.»
[Скопировать ссылку]

## 9. Расчёт лучших интервалов
Раздел доступен всем участникам (не только организатору). Список лучших окон отображается под тепловой картой.
Кнопка:

```text
Найти общие интервалы
```
### 9.1. Алгоритм
Анализ идёт по отдельным ячейкам. Для каждой ячейки рассчитываются:
- количество Available;
- количество IfNeeded;
- количество «не может» (общее число проголосовавших − Available − IfNeeded);
- список участников в каждой категории;
- рейтинг ячейки.
Кого считать проголосовавшим:
Участник считается проголосовавшим, если у него есть хотя бы одна запись в Availability или HasNoSuitableTime = true.
Кого не учитывать:
Участники, у которых нет ни одной записи в Availability, и при этом HasNoSuitableTime = false, не учитываются в расчёте рейтинга вообще. Они не влияют ни на числитель, ни на знаменатель. При этом они отображаются в панели организатора в категории «Зашли, но не проголосовали» — для контроля.
Рейтинг ячейки:

```text
Score = AvailableCount * 100
      + IfNeededCount * 20
      - CannotCount * 100
```
Приоритеты при равном рейтинге:
- все проголосовавшие участники Available;
- максимальное Available;
- минимальное Cannot;
- максимальное IfNeeded;
- более раннее время.
### 9.2. Отображение результата
Список лучших ячеек под тепловой картой. Каждая ячейка содержит:
дату и день недели;
время начала и окончания в часовом поясе текущего пользователя;
количество Available, IfNeeded, «не может»;
список участников по категориям;
рейтинг.
Пример:

```text
Понедельник, 12 октября, 10:00–11:00 (МСК)
  Свободны: Иван, Мария, Пётр (3 из 4)
  Если нужно: Аня (1)
  Не могут: —
  Рейтинг: 320
```
### 9.3. Случай отсутствия полного согласия
Если ни одна ячейка не имеет полного согласия, система:
- показывает лучшие частичные варианты;
- добавляет явную пометку «Полного согласия нет»;
- отображает для каждого варианта, кто именно не может.
### 9.4. Empty state
Если ни один участник ещё не проголосовал — список пуст, показывается:
«Пока никто не отметил доступность. Результаты появятся, когда кто-то проголосует.»

## 10. Панель организатора
URL:

```text
/manage/{ShortCode}
```
### 10.1. Авторизация
При входе на /manage/{ShortCode} авторизация проверяется в следующем порядке:
Cookie OwnerToken — если cookie есть и совпадает с Meeting.OwnerToken, доступ разрешён.
Query-параметр key — если cookie нет или он не совпадает, проверяется параметр key из URL:
если key совпадает с Meeting.OwnerToken, доступ разрешён;
устанавливается cookie OwnerToken;
выполняется редирект на /manage/{ShortCode} без key в URL (чтобы ключ не оставался в адресной строке и не утекал через Referer).
Если ни cookie, ни key не сработали — показывается страница:
«Доступ запрещён. Войдите как организатор или используйте ссылку управления.»
Дополнительно: для страницы /manage устанавливается заголовок Referrer-Policy: no-referrer. Ключ в URL не логируется на сервере.
### 10.2. Активная встреча
Показываются:
- название и статус встречи;
- режим хранения;
- ссылка для участников с кнопкой копирования;
- QR-код;
- кнопки шаринга (Telegram, WhatsApp, ВКонтакте, Email);
- количество участников в трёх категориях:
  - Отметили доступность — Иван, Мария, Пётр (3).
  - Отметили «нет подходящего времени» — Аня (1).
  - Зашли, но не проголосовали — Олег, Катя (2).
- для каждого проголосовавшего — его часовой пояс;
- тепловая карта;
- список лучших интервалов;
- кнопка «Найти общие интервалы»;
- кнопка закрытия встречи;
- кнопка «Пересоздать ссылку управления»;
- кнопка «Удалить встречу навсегда».
### 10.3. Закрытая встреча
Показываются:
- итоговое окно (или сообщение «Встреча закрыта без выбранного времени», если `SelectedStartTime = null`);
- экспорт результатов (`.ics`, CSV, JSON);
- кнопка добавления в календарь.
### 10.4. Формат отображения времени
Все даты и время показываются на русском языке:
12 октября 2026, понедельник — не Oct 12, 2026.
10:00–12:00 — не 10:00 AM – 12:00 PM.
Часовой пояс показывается явно: 10:00 (МСК) или 10:00 (Europe/Moscow).

## 11. Выбор итогового слота и закрытие встречи
### 11.1. Закрытие с выбранным окном
Организатор выбирает одно из лучших окон (или ячейку) и нажимает:

```text
Закрыть встречу с этим окном
```
Система:
- записывает `SelectedStartTime` и `SelectedEndTime` (UTC);
- устанавливает `Status = Closed`;
- записывает `ClosedAt`;
- запрещает изменения голосов;
- показывает итоговое время всем участникам.
### 11.2. Закрытие без выбранного окна
Организатор может закрыть встречу без выбранного окна — например, если никто не проголосовал или ни одно время не подошло.
Организатор нажимает «Закрыть встречу» без выбора окна. Показывается подтверждение:
«Вы закрываете встречу без выбранного времени. Это значит, что встреча не состоится. Продолжить?»
[Отмена] [Закрыть]
После подтверждения:
- `Status = Closed`;
- `ClosedAt = now`;
- `SelectedStartTime` и `SelectedEndTime` остаются `null`.
На странице встречи отображается:
«Встреча закрыта без выбранного времени.»
### 11.3. Автозакрытие
Автозакрытие отсутствует. Даже если найдено ровно одно идеальное окно, встреча закрывается только по действию организатора.

## 12. Жизненный цикл встречи
### 12.1. Архивация (для RetentionMode = KeepForever)
Через 90 дней неактивности встреча с RetentionMode = KeepForever автоматически переводится в Status = Archived:
- `GridCell` не удаляются;
- `Availability` не удаляются;
- `Participant` не удаляются;
- `SelectedStartTime` / `SelectedEndTime` сохраняются.
Для встреч с RetentionMode = DeleteAfterLastDay архивация не применяется — они удаляются по правилу раздела 12.2.
Глобальный query filter исключает из обычных запросов встречи со статусами Archived и Deleted:

```csharp
modelBuilder.Entity<Meeting>()
    .HasQueryFilter(x => x.Status != MeetingStatus.Archived
                      && x.Status != MeetingStatus.Deleted);
```
Оба статуса считаются «неактивными» и не показываются пользователям. Для аналитики и админки фильтр отключается через IgnoreQueryFilters().
### 12.2. Удаление по RetentionMode = DeleteAfterLastDay
Фоновая задача Hangfire запускается раз в сутки (например, в 03:00 UTC).
Условие срабатывания:
- `RetentionMode = DeleteAfterLastDay`;
- независимо от текущего `Status` (встреча может быть `Active`, `Closed`, `Archived`);
- в часовом поясе организатора наступил день, следующий за `GridEndDate`.
Пример: GridEndDate = 12 октября, TimeZone = Europe/Moscow. Встреча удаляется после 00:00 14 октября по московскому времени.
Что удаляется:
- `Availability` — каскадно;
- `GridCell` — каскадно;
- `Participant` — каскадно;
- `Invitation` — каскадно;
- `Meeting` — сама встреча.
Никаких заглушек не остаётся.
### 12.3. Ручное удаление организатором
Организатор нажимает на панели управления «Удалить встречу навсегда».
Модальное подтверждение:
«Это действие необратимо. Ссылка встречи перестанет работать. Все отметки участников будут удалены. Продолжить?»
[Отмена] [Удалить]
После подтверждения:
Availability, GridCell, Participant, Invitation удаляются сразу.
Meeting переводится в Status = Deleted, записывается DeletedAt.
По ссылке /m/{ShortCode} отображается:
«Встреча удалена организатором.»
Через 30 дней Hangfire полностью удаляет Meeting со Status = Deleted и DeletedAt < today - 30.

## 13. Ссылка управления
### 13.1. Формат

```text
https://timemeet.ru/manage/{ShortCode}?key={OwnerToken}
```
### 13.2. Жизненный цикл
При создании встречи — показывается один раз в модальном окне с кнопкой «Скопировать».
На панели управления — кнопка «Пересоздать ссылку»:
генерирует новый OwnerToken;
старая ссылка перестаёт работать;
новая показывается в модальном окне с предупреждением: «Старая ссылка управления перестала работать. Сохраните новую.»
Cookie с OwnerToken обновляется автоматически.

Страница /manage отдаётся с заголовком Referrer-Policy: no-referrer.
Ключ в URL не логируется на сервере.
При успешной авторизации через key выполняется редирект на /manage/{ShortCode} без key в URL.

## 15. Безопасность
ShortCode генерируется криптостойко.
OwnerToken и ParticipantToken генерируются через RandomNumberGenerator.
Cookie имеет флаги HttpOnly, Secure в production и SameSite=Lax.
OwnerToken хранится в HttpOnly-cookie сроком 30–90 дней.
Все входные данные валидируются.
MaxLength для текстовых полей: Title — 100, Description — 1000, OrganizerName / DisplayName — 50.
Нельзя сохранить доступность для другой встречи.
Нельзя менять голос закрытой встречи.
Rate limiting на создание встреч.
Rate limiting по IP на создание Participant.
Лимит: participants × cells_per_meeting ≤ 50 000.
Формы защищаются от CSRF.

## 21. Критерии готовности MVP
MVP считается готовым, если:
- пользователь может создать встречу со свободной сеткой на полные дни;
- организатор после создания попадает на страницу голосования и может проголосовать;
- участник может проголосовать без регистрации;
- время отображается в часовом поясе участника;
- все участники видят тепловую карту с отметками и список лучших интервалов;
- переключатель «Моя доступность» / «Показать всех» работает;
- галочка «Ни одно время не подходит» работает;
- организатор может закрыть встречу с выбранным окном;
- организатор может закрыть встречу без выбранного окна;
- организатор может удалить встречу вручную;
- удаление по `RetentionMode = DeleteAfterLastDay` работает через Hangfire;
- итоговый слот экспортируется в `.ics`;
- ссылка встречи сохраняется;
- приложение запускается через `docker-compose up`;
- миграции создаются и применяются вручную через терминал;
- код опубликован под лицензией MIT.

## 22. Итоговая схема процесса

```text
Создание встречи (интервал дат, шаг, режим хранения)
        ↓
Организатор получает ссылку управления и попадает на страницу голосования
        ↓
Участники (включая организатора) отмечают доступность на тепловой карте
        ↓
Система рассчитывает лучшие интервалы
        ↓
Организатор видит тепловую карту и список лучших интервалов
        ↓
Организатор выбирает итоговое окно (или закрывает без окна)
        ↓
Встреча закрывается
        ↓
   ┌────────────────────────────────────┐
   │ RetentionMode = KeepForever?       │
   │   Да → архивация через 90 дней     │
   │   Нет → удаление через день после  │
   │         GridEndDate (TZ организатора)│
   └────────────────────────────────────┘
        ↓
Экспорт в календарь
```
